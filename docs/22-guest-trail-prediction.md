# 22 - 게스트 자기 궤적 지연 (로컬 예측)

## 증상 (정현 보고)
> 온라인 게스트 화면에서 자기 궤적이 캐릭터보다 늦게 따라온다.

## 원인 — 구조적 지연이다. 버그가 아니다.
온라인은 방장이 전부 계산한다(host-authoritative). 게스트의 궤적은 이 길을 돌아야 그려진다.
```
내가 움직인다 → 방장에게 내 위치를 올린다 → 방장이 칸을 판정한다
              → 방장이 바뀐 칸을 뿌린다 → 내 화면에 그려진다
```
**왕복 한 번이 통째로 늦는다.** 방장은 자기 궤적을 그 자리에서 그리니 멀쩡하고,
게스트만 캐릭터가 앞서고 선이 뒤따라오는 그림이 된다.

---

## 고친 방법 — 화면에만 미리 깔아 둔다 (클라이언트 예측)

게스트가 지나는 칸을 **자기 화면에만** 먼저 칠해 두고, 방장 확정이 오면 그걸로 덮는다.

```js
const pred = new Uint8Array(TOTAL);    // 예측 궤적 — 렌더 전용
```

### 반드시 지킨 선
| | |
| --- | --- |
| **판정에 영향 없음** | `trail`·`owner`를 **한 번도 안 건드린다.** 죽음·점령·상대 궤적 충돌은 계속 방장만 판정한다 |
| **점령은 예측 안 함** | 집에 닿아도 아무것도 안 칠한다. 방장이 확정해 줄 때까지 기다린다 |
| **어긋나면 스스로 걷힘** | 확정 없이 `PRED_TTL`(1.5초)이 지난 예측은 지워진다 |
| **확정이 오면 즉시 양보** | 방장이 보낸 칸은 `pred[i] = 0`으로 털고 확정 값을 그린다 |
| **죽으면 통째로 버림** | 사망·부활·경기 시작·종료에서 전부 지운다 |

### 칸 잇기는 같은 방식
`stepCells()`와 똑같이 마지막 칸에서 지금 칸까지 한 칸씩 이어 붙인다.
프레임이 떨어져도 예측 궤적에 구멍이 안 난다. 64칸을 넘게 벌어지면(리스폰 등) 잇지 않는다.

### 그리는 쪽만 두 군데 고쳤다
```js
const t = trail[i] || (pred[i] ? me.id : 0);   // paint() 와 syncTrailMesh()
```
미니맵은 `paint()`가 칠한 픽셀을 그대로 쓰므로 따라온다.

## 검증

### (1) 지연을 넣고 화면 지연을 직접 쟀다
`index.html`의 로직을 그대로 떼어 방장 1 + 게스트 2를 띄우고, relay에 지연을 넣었다.
**게스트가 지난 칸 중 아직 자기 화면에 안 그려진 칸 수**를 0.1초마다 센다.

| 조건 | 예측 끔 | **예측 켬** | 최종 점령 (세 명) |
| --- | --- | --- | --- |
| 기본 | 평균 0.2칸 · 최대 1칸 | **0칸 · 최대 0칸** | 1.86 / 1.86 / 1.86% |
| 왕복 400ms | 평균 1.5칸 · 최대 4칸 | **0칸 · 최대 0칸** | 1.86 / 1.86 / 1.86% |
| 보고 400ms (11 문서 조건) | 평균 0.4칸 · 최대 2칸 | **0칸 · 최대 0칸** | 1.86 / 1.86 / 1.86% |
| 왕복+보고 400ms | 평균 1.7칸 · 최대 6칸 | **0칸 · 최대 0칸** | 1.86 / 1.86 / 1.86% |

표본은 조건마다 1,188개다. **모든 조건에서 지연이 0칸이 되고, 최종 점령은 여덟 가지 설정에서
전부 똑같다.** 예측이 결과를 바꾸지 않는다는 뜻이다.

### (2) 격자가 오염되지 않는가
같은 시험에서 방장 격자와 게스트 격자를 칸 단위로 비교했다.
```
                        12초 시점        30초 시점
왕복 400ms · 예측 끔     6칸 다름 / 0      0 / 0
왕복 400ms · 예측 켬     6칸 다름 / 0      0 / 0      ← 예측을 켜도 똑같다
```
12초의 6칸은 **아직 날아오는 중인 칸**이고 30초에는 0이 된다.
**예측을 켜고 끄고가 완전히 같다** — 예측이 `trail`·`owner`를 안 건드린다는 증거다.

### (3) 실제 브라우저 온라인 2인
로컬 서버라 망 지연이 거의 없는 조건에서, 같은 방식으로 쟀다.
| | 방장 | 게스트 |
| --- | --- | --- |
| 예측 끔 | 0.40칸 | **0.71칸** ← 게스트만 더 늦다 (보고된 증상) |
| **예측 켬** | 0.40칸 | **0.39칸** ← 방장과 같아졌다 |

> 0.4칸은 **측정 장치의 바닥값**이다. 시험 코드가 위치를 옮긴 직후에 재기 때문에
> 아직 그 프레임의 렌더가 안 돈 상태다. 방장에게도 똑같이 깔리는 값이라,
> **게스트에게만 있던 추가 지연이 사라졌다**는 게 이 표가 말하는 전부다.

## 알려진 이슈
1. **상대의 궤적은 여전히 왕복만큼 늦다.** 예측은 내 궤적만 한다. 남의 위치를 앞질러
   찍으면 틀렸을 때 더 헷갈린다고 봤다.
2. **판정이 어긋나면 예측이 잠깐 남는다.** 예를 들어 방장이 나를 죽였는데 그 소식이
   오기 전에 깔린 예측은 최대 1.5초(`PRED_TTL`)까지 화면에 남을 수 있다.
   사망 소식이 오면 즉시 전부 지우므로 실제로는 왕복 시간만큼이다.
3. **점령은 예측하지 않는다.** 집에 닿는 순간의 점령은 여전히 왕복만큼 늦게 칠해진다.
   지시하신 대로 일부러 안 넣었다 — 어긋나면 훨씬 혼란스럽다.
4. 14·16·19 문서의 판단 대기 건은 그대로다.
