# 26-b - 게스트 궤적이 그려지다 사라짐 — 실제 원인은 경기 중 재접속이었다

## 증상 (정현 실플레이)
> 게스트 화면에서 자기 궤적이 보였다가 순서대로 사라지고 점령 안 됨.

예측(`pred`)만 그려지고 방장 확정이 안 와 `PRED_TTL`(1.5초) 뒤 깔린 순서대로 걷히는 동작이다.
**방장이 그 게스트 입력을 처리하지 못하고 있다**는 뜻이고, 거기까지는 진단이 맞았다.

---

## 1. 지시받은 원인(`applyInput` deaths 폐기)은 재현되지 않았다

먼저 `applyInput`에 **폐기 사유 카운터**를 심고 2탭 세션을 그대로 돌렸다.
사각형으로 나갔다 돌아오는 경로 · 사망·리스폰 · 다시하기(2판) 전부.

```
1판 게스트 정체성: myId=adf822af  meId=2  meNetId=adf822af  meDeaths=0
             방장이 아는 ents [id,netId,deaths]: [[1,'0a529caa',0], [2,'adf822af',0]]
[1판] 중간 궤적 19칸 → 복귀 후 땅 137칸 · 궤적 0
     방장 입력: {total: 156, ok: 156}          ← 하나도 안 버렸다
[2판] 중간 궤적 19칸 → 복귀 후 땅 137칸 · 궤적 0
     방장 입력: {total: 163, ok: 163}
```

게스트 `me.deaths`를 **일부러 7로 어긋나게** 만들어도 입력은 127/127 전부 받아들여졌다.
`applyState`가 `deaths !== e.deaths` 조건에 걸려 **한 틱 뒤 게스트 쪽을 방장 값으로 되돌려 놓기**
때문이다. 즉 **"한 번 어긋나면 회복 경로가 없다"는 전제가 사실이 아니었다.**
자연 발생한 불일치도 1회(`[보고n=1, 방장=0]`) 뿐이고 한 틱 만에 수습됐다.

> 처음 돌린 경로에서는 점령이 안 됐는데(`notAlive` 22회), 그건 **내 테스트 경로가
> 자기 궤적을 되밟아 게스트를 죽인 것**이었다. 경로를 사각형으로 바꾸니 바로 점령됐다.
> 테스트 쪽 실수이고 게임 문제가 아니었다 — 그대로 적어 둔다.

## 2. 실제 원인 — 경기 중 소켓이 한 번 끊기면 조용히 경기에서 빠진다

증상과 맞는 다른 경로를 찾아 **게스트 소켓만 끊어 봤다** (와이파이가 한 번 끊기는 상황).

```
시작        — 게스트 myId=2a677df8  meNetId=2a677df8   방장이 아는 netId=['20474d46','2a677df8']
정상 구간   — 방장 입력 {total: 41, ok: 41} · 궤적 6칸

▼ 소켓 끊기 → 1초 뒤 자동 재접속

재접속 후   — 게스트 myId=8bf6b118 (바뀜!)  me.netId=2a677df8 (그대로)  online=true screen=game
              방장이 아는 netId=['20474d46','2a677df8']   ← 옛 id 그대로
재접속 후 이동 — 방장 입력 {}                ← applyInput 이 아예 호출되지 않는다 (total 0)
                 방장이 본 게스트 궤적 0칸
```

연쇄는 이렇다.

| 단계 | 일어나는 일 |
| --- | --- |
| 1 | 소켓이 끊긴다. 서버는 그 클라이언트를 **방에서 빼고** 종료 처리한다 |
| 2 | 방장은 `peer leave`를 받아 그 사람을 **사망 처리하고 궤적을 지운다** (`alive=false`, `respawn=1e9`) |
| 3 | 1초 뒤 게스트가 재접속한다. 서버가 **새 id**를 발급하고 `myId`가 바뀐다 |
| 4 | 새 클라이언트는 **방에 속해 있지 않다.** 그래서 `{k:'i'}` 보고가 relay 되지 않고 **방장까지 가지도 못한다** |
| 5 | 게스트 화면만 `screen='game'`, `online=true`로 남는다. `predictTrail()`은 계속 돌아 예측을 깔고, 확정이 영원히 안 오니 **1.5초 뒤 깔린 순서대로 지워진다** |

`sock.onclose`가 `room`·`create` 화면만 처리하고 **`game` 화면은 아무 것도 하지 않았다.**
그래서 끊긴 사실조차 알려 주지 않았다 — 정현이 본 그림이 이것이다.

`applyInput`의 폐기 카운터로도 이 경우는 `notFound`가 아니라 **`total`이 아예 안 느는 것**으로
구분된다. 보고가 방장까지 오지 못했다는 뜻이다.

## 수정 — 네 군데

### (1) `applyInput` 영구 폐기 제거 (지시 1)
```js
  if (d.n !== undefined && d.n !== e.deaths) {
    // 전에는 여기서 보고를 통째로 버렸다. 좌표는 받아 두고 세기만 한다 —
    // '죽기 직전 옛 좌표'를 막는 일은 아래 warpT 분기가 이미 맡고 있다.
    DROPS.deaths++;
  }
```
재현되지 않았지만 **한 번 어긋나면 그 틱의 보고가 사라지는 건 사실**이고, 막아 주는 값이
`warpT` 분기와 겹친다. 세어 두고 받는 쪽이 맞다.

### (2) 내 사망 횟수는 방장 값으로 무조건 맞춘다 (지시 1 후단)
```js
      if (deaths !== e.deaths || (!was && e.alive)) { clearPred(); pos.set(...); }
      e.deaths = deaths;        // ← 조건 밖으로 꺼냈다. 방장 값이 늘 기준이다.
```
전에는 조건 **안**에 있어서, 조건이 안 타는 경로가 생기면 어긋난 채 남을 수 있었다.

### (3) 경기 중 끊김을 조용히 두지 않는다 — 실제 원인에 대한 수정
```js
    } else if (online && screen === 'game' && !matchOver) {
      // 재접속하면 새 id 가 발급되어 그 경기로는 돌아갈 수 없다.
      // 조용히 두면 자기 궤적만 그려지다 1.5초 뒤 사라지고 점령이 안 되는 것처럼 보인다.
      matchOver = true;
      netEndMatch();
      myRoom = null;
      toast('연결이 끊겨 경기에서 빠졌습니다');
      showScreen('menu');
    }
```
**경기에 못 돌아가는 건 그대로다** (그건 기능이고 아래 남은 이슈에 적었다).
대신 **왜 안 되는지 알려 주고 메뉴로 보낸다.** 유령 궤적을 그리며 서 있지 않는다.

### (4) 폐기 사유 카운터 (지시 3)
```js
const DROPS = { total, ok, notFound, notAlive, deaths, warp, lastFrom, knownIds };
window.__lgDrops = DROPS;                     // 콘솔에 `__lgDrops` 로 바로 본다
```
방장의 `hostTick`에서 버린 보고가 생기면 **5초마다 한 줄**만 남긴다.
```
[입력 폐기] 총 1240 · 받음 1198 · 명단없음 0 · 사망중 40 · 사망횟수불일치 2 · 리스폰대기 0
```
`notFound`가 있으면 `{from, known}`도 같이 찍어 **어느 id가 명단에 없는지** 바로 보인다.

## 감독 확인 요청 / 남은 이슈
1. **경기 중 재접속은 여전히 그 경기로 못 돌아간다.** 이번엔 "왜 못 하는지 알려 주고
   메뉴로 보내는" 것까지만 했다. 돌아가게 하려면 **서버 작업이 필요하다** —
   방 멤버십을 끊긴 뒤에도 잠시 유지하고, 재접속 때 옛 id 를 되찾는 `rejoin` 경로,
   `room.playing` 중 입장 허용. **별건으로 올릴지 판단 부탁드린다.** 와이파이가
   한 번 끊기면 그 판은 끝나는 지금 동작이 괜찮은지도 같이 봐 주시면 좋겠다.
2. **지시받은 deaths 경로는 재현되지 않았다.** 그래도 하드닝은 넣었고, 앞으로 실제로
   그 사유가 뜨면 `__lgDrops.deaths` 가 올라간다. 실플레이에서 또 같은 증상이 보이면
   **방장 콘솔에 `__lgDrops` 를 찍어 보내 주시면** 다섯 사유 중 어디인지 바로 가려진다
   (`total` 이 안 늘어 있으면 이번과 같은 끊김이다).
3. 26 문서의 64칸 문턱 건, 25 문서의 판단 네 건은 그대로다.
