# 19 - 스킬 슬롯 + 아이템 (인벤토리형)

## 무엇을 했나
맵에 스킬 아이템이 떨어진다. **밟으면 바로 터지지 않고 빈 슬롯에 들어가고**,
`1`·`2`·`3` 키로 꺼내 쓴다. 온라인에서는 스폰·획득·발동·효과를 전부 방장이 계산한다.

---

## 1. 사양

### 슬롯
- 화면 **우상단**, 미니맵 바로 아래에 **3칸**. 각 칸에 번호·아이콘·이름이 뜨고 빈 칸은 `빈 칸`.
- 발동 중인 효과는 슬롯 아래에 남은 시간과 함께 뜬다.
- 아이템을 밟으면 **1번 → 2번 → 3번 순서로 빈 칸을 채운다.**
- **세 칸이 다 차 있으면 밟아도 안 줍는다.** 아이템은 그 자리에 그대로 남는다.
- `1`/`2`/`3`을 누르면 그 칸의 스킬이 발동하고 **그 칸만 비워진다.** 빈 칸을 눌러도 아무 일 없다.
- **죽으면 슬롯과 효과를 전부 잃는다.** 땅을 전부 잃는 것과 같은 취급이다.

### 스킬 4종
| 아이콘 | 이름 | 효과 | 지속 |
| --- | --- | --- | --- |
| ⚡ 노랑 | 속도 부스트 | 이동 속도 ×**1.45** (달리기 11 → **16.0 m/s**, 걷기 6 → 8.7) | **6초** |
| 🛡 파랑 | 궤적 무적 | 내 궤적이 안 잘린다. 밟혀도, 포위당해도 안 죽는다 | **6초** |
| ▣ 보라 | 점령 확대 | **다음 점령 때** 가진 칸 바깥으로 테두리를 한 겹 더 두른다 | 1회 |
| ↩ 초록 | 순간 귀환 | 그린 궤적을 그 자리에서 점령 처리하고 자기 영역으로 돌아간다 | 즉시 |

### 수치 (정현이 조정할 값)
```js
const SLOTS      = 3;      // 슬롯 칸 수
const ITEM_MAX   = 8;      // 맵에 동시에 놓이는 최대 개수
const ITEM_EVERY = 4;      // 스폰 주기 (초)
const BOOST_MUL  = 1.45;   // 속도 부스트 배수
SKILLS[1].sec = 6;         // 속도 부스트 지속
SKILLS[2].sec = 6;         // 궤적 무적 지속
```
스폰은 **소유자도 궤적도 없는 빈 땅에만** 떨어지고, 가장자리 6칸은 뺀다.

## 2. 동기화 구조 (host-authoritative)

서버는 **한 줄도 안 고쳤다.** relay가 이미 임의의 데이터를 그대로 전달하므로
새 메시지 종류만 얹으면 된다. 그래서 `ws_server.py` 백업·`py_compile`도 필요 없었다.

```
게스트 → 방장   {k:'u', s:칸번호}          1/2/3을 눌렀다는 사실만 올린다
방장   → 전원   {k:'s', ..., e:[...], it:[...]}
                 e[] 각 참가자: … 슬롯(3칸을 3비트씩 묶음) · 부스트 · 무적 · 확대
                 it[] 아이템 목록: [셀번호, 종류, 셀번호, 종류, …]
```
- **아이템 목록은 매 틱 통째로 보낸다.** 최대 8개(숫자 16개)라 부담이 없고,
  통째로 덮어쓰면 스폰·획득이 어긋날 일이 없다. 증분 전송은 쓰지 않았다.
- 슬롯은 한 칸이 0~4라 3비트면 된다. **세 칸을 한 숫자로 묶어 보낸다.**
- 게스트는 자기 슬롯조차 직접 안 고친다. **방장이 계산한 값을 받아 그린다.**

---

## 3. 규칙에 닿는 부분

- **획득**: 칸에 들어가는 순간 `takeItem()`을 먼저 부른다. 그 칸에서 죽더라도
  사망 처리가 슬롯을 비우므로 이득이 없다.
- **궤적 무적**: 남이 내 궤적을 밟아도 안 죽는다. 대신 **밟은 쪽은 그 칸을 못 가진다** —
  그냥 지나가고 자기 궤적을 놓지 못한다. 튕겨 나오는 셈이라 그쪽 궤적에 구멍이 난다.
  포위(flood-fill)로도 무적인 상대는 못 가둔다.
- **점령 확대**: 이번 점령에서 새로 가진 칸만 모아 그 바깥 한 겹을 더 가진다.
  영토 전체를 부풀리지 않으므로 크기가 예측 가능하다. 테두리에 남의 궤적이 있으면
  포위와 같은 취급으로 그 주인이 죽는다(무적이면 건드리지 않는다).
- **순간 귀환**: `capture()`를 먼저 돌려 궤적을 점령으로 바꾸고 집으로 옮긴다.
  집을 빼앗겼으면 가장 가까운 내 땅을 다시 찾는다. 온라인에서는 17단계의 리스폰
  보호(`warpT`)를 걸어 옛 좌표 보고가 선을 긋지 않게 한다.

## 4. 봇
- **줍는다.** 방향을 고를 때 가는 길에 아이템이 있으면 가산점(+6)을 주고,
  판단 주기마다 26칸 안에 아이템이 있으면 `grab` 국면으로 들러서 줍는다.
  슬롯이 차 있으면 안 들른다.
- **상황을 보고 쓴다.**
  | 스킬 | 봇이 쓰는 때 |
  | --- | --- |
  | 순간 귀환 | 위험하고 궤적이 60칸을 넘었을 때 |
  | 궤적 무적 | 적이 내 궤적에 붙었을 때 |
  | 속도 부스트 | 사냥 추격 중이거나, 위험한 복귀 중일 때 |
  | 점령 확대 | 확장 중이고 궤적이 20칸을 넘었을 때 |
- 슬롯이 꽉 찼는데 쓸 때가 아니면 **자리를 비우려고** 덜 급한 것(확대·부스트)을 쓴다.

## 알려진 이슈 / 판단이 필요한 지점
1. **수치가 전부 첫 안이다.** 스폰 4초·상한 8개·지속 6초·배수 1.45.
   빡빡하거나 헐겁다 싶으면 상수만 고치면 된다. 위 2번 항목에 위치를 적어 두었다.
2. **궤적 무적으로 튕겨 나온 쪽은 궤적에 구멍이 난다.** 그 칸을 못 가지기 때문이다.
   폐곡선이 안 닫혀 점령이 실패할 수 있다. 무적의 값어치를 높게 본 설계인데,
   "그냥 통과하되 상대 궤적을 덮어쓴다"로 바꾸면 무적이 무의미해진다. 판단 부탁드린다.
3. **점령 확대가 남의 궤적을 덮으면 그 주인이 죽는다.** 포위와 같은 취급이다.
   의도치 않은 킬이 나올 수 있다.
4. **아이템이 남의 땅 위에 남아 있을 수 있다.** 점령으로 땅이 덮여도 아이템은 안 지운다.
   남의 영역 안으로 주우러 들어가는 그림이 되는데, 미끼로 쓸 수 있어 그대로 뒀다.
5. 14·16 문서의 온라인 밸런스 건은 여전히 방침 대기 중이다.
