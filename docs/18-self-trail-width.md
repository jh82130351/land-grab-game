# 18 - 지금 그리는 궤적을 밟아도 죽던 문제

## 증상 (정현 정정)
> 궤적은 폭이 있는 띠다. 내가 지금 밟고 지나는 궤적 및 그 폭은 내가 딛는 길이므로
> 밟아도 죽으면 안 된다. 지금은 그 폭 안까지 '자기 궤적 충돌'로 판정해 억울하게 죽는다.

## 원인 — 내 궤적이면 방금 그은 칸이든 옛 칸이든 똑같이 죽였다
```js
const t = trail[i];
if (t) {                                  // 궤적을 밟았다 → 그 궤적 주인이 죽는다
  const victim = ents[t - 1];
  if (victim) kill(victim, ent, t === ent.id ? '자기 궤적에 걸림' : ...);
```
**언제 그은 칸인지를 보지 않았다.** 좁게 꺾거나 지그재그로 가면 방금 지난 칸을 다시
밟게 되는데, 그건 주행이지 사고가 아니다. 그런데 규칙은 그걸 옛 궤적을 가로지른 것과
똑같이 처리했다.

화면에서 궤적은 폭이 있는 띠로 보인다. 격자 위에서는 한 칸짜리 선이지만, 대각선으로
달리면 `stepCells()`가 계단꼴로 칸을 메우기 때문에 **실제로 딛는 길은 한 칸보다 두껍다.**
그 두께 안을 밟는 게 억울한 죽음의 정체다.

---

## 바뀐 판정 규칙

```js
const FRESH_TAIL = 18;     // '지금 딛고 있는 길'로 치는 최근 구간 (칸)

function isFreshTrail(ent, i) {          // 최근 18칸 안에 그은 칸인가
  const n = ent.trail.length;
  for (let k = n - 1, c = 0; k >= 0 && c < FRESH_TAIL; k--, c++)
    if (ent.trail[k] === i) return true;
  return false;
}
```

| 밟은 칸 | 전 | **후** |
| --- | --- | --- |
| 내 궤적 · **최근 18칸 안** | 사망 | **그냥 통과** |
| 내 궤적 · 그보다 앞서 그은 칸 | 사망 | 사망 (그대로) |
| 남의 궤적 | 그 주인 사망 | 그 주인 사망 (그대로) |
| 내 영역 | 점령 판정 | 점령 판정 (그대로) |

**18칸은 달리기(11 m/s)로 약 2.5초, 걷기(6 m/s)로 약 4.5초 동안 지나는 거리다.**
좁은 회전이나 지그재그로 다시 밟게 되는 범위를 넉넉히 덮는다. 상수 하나만 고치면 조절된다.

통과할 때는 **궤적에 다시 넣지 않는다.** 같은 칸이 `ent.trail`에 두 번 들어가면
길이가 부풀어 다른 판단이 어긋난다. 이미 내 궤적인 칸이므로 그대로 두고 지나간다.

### 점령(flood-fill)은 왜 영향이 없나
한 칸은 **내 궤적이면서 동시에 내 영역일 수 없다.** 궤적을 놓는 분기는 `owner[i] !== ent.id`
일 때만 돌기 때문이다. 그래서 통과 처리로 빠져나가도 **점령 판정을 건너뛰는 경우는 없다.**
실제로 깨끗한 네모의 점령량이 수정 전후 소수점까지 같다 (아래 검증).

## 알려진 이슈 / 판단이 필요한 지점
1. **둘레가 18칸을 넘는 고리는 여전히 자멸이다.** 반경 4칸(둘레 32칸)짜리 원을 닫으면
   죽는다. "그 정도 작은 원도 살아야 한다"면 `FRESH_TAIL`만 올리면 된다.
   다만 올릴수록 **작은 고리로 상대를 유인해 가두는 수**가 안전해지므로, 어디까지가
   '딛는 길'이고 어디부터가 '고리'인지는 기획 판단이라 보고 18칸으로 두었다.
2. **되돌아오기도 18칸까지만 안전하다.** 왔던 길을 40칸 되짚으면 죽는다.
3. 14·16 문서의 온라인 밸런스 건(무제한 궤적, 숨어 기다리기)은 방침 대기 중이다.

## 감독 확인 요청
1. **좁게 돌거나 지그재그로 달려 보고 억울하게 죽는 일이 없는지.**
2. **앞서 그어 둔 선을 일부러 가로질러 보고 여전히 죽는지.** 자멸 자체는 살아 있어야 한다.
3. **알려진 이슈 1번** — 반경 4칸짜리 원까지 살려야 하는지. 살려야 하면 숫자만 올리겠다.
