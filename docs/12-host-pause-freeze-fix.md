# 12 - 게스트 궤적이 여전히 안 만들어지던 진짜 원인 (방장이 멈춰 있었다)

## 증상 (정현 보고)
> 버그가 안 고쳐졌어

11번에서 칸 잇기를 넣었는데도 게스트 궤적이 안 생긴다는 보고다.
11번 수정 자체는 맞았다. **그보다 한 단계 앞에서 판정이 아예 안 돌고 있었다.**

## 원인 — 방장 창의 포인터 잠금이 풀리면 경기 전체가 멎는다
루프는 이랬다.
```js
const active = (screen === 'game' || screen === 'lobby') && locked;
if (screen === 'game' && active) stepMatch(dt);   // ← locked가 false면 판정을 건너뛴다
```
`locked`는 **내 창의 마우스 포인터 잠금** 여부다. 다른 창을 클릭하거나 ESC를 누르거나
탭을 바꾸면 브라우저가 잠금을 자동으로 푼다.

온라인은 host-authoritative다. **모든 참가자의 칸 판정·점령·타이머를 방장 혼자 계산한다.**
그런데 방장이 잠금을 잃는 순간 `stepMatch`가 통째로 안 돌았다. 결과는 이렇다.

| | 방장 창 | 게스트 창 |
| --- | --- | --- |
| 이동 | 멈춤(일시정지 화면) | **정상** (자기 카메라는 로컬에서 돈다) |
| 궤적 | 안 생김 | **안 생김** |
| 점령 | 안 됨 | **안 됨** |
| 남은 시간 | 멈춤 | **멈춤** |

방장은 "내가 일시정지했으니 멈추는 게 당연하다"고 느낀다. 게스트는 **멀쩡히 걸어 다니는데
궤적만 안 그려진다.** 정현님이 본 "게스트는 경로가 안 만들어진다"가 바로 이 그림이다.

### 왜 11번 검증에서는 안 걸렸나
11번 실측은 스크립트로 두 클라이언트를 돌렸다. 두 창 모두 계속 포커스를 유지한 상태라
잠금이 풀릴 일이 없었다. **한 PC에서 창 두 개를 띄워 번갈아 조작하면 무조건 재현된다.**
게스트 창을 클릭하는 그 순간 방장 창의 잠금이 풀리기 때문이다.

`hostTick()`은 잠금과 무관하게 계속 돌고 있었다. 그래서 상태 스냅샷은 계속 날아갔고
"연결은 멀쩡한데 궤적만 없다"는 더 헷갈리는 모습이 됐다.

## 고친 내용 — 방장의 판정은 잠금과 분리한다
```js
// 온라인 방장은 전원의 판정을 맡는다. 내 포인터 잠금이 풀렸다고(다른 창 클릭·ESC·탭 전환)
// 멈춰버리면 게스트의 궤적·점령·타이머가 통째로 멎는다. 방장은 잠금과 무관하게 계속 돈다.
if (screen === 'game' && (active || (online && iamHost && !matchOver))) stepMatch(dt);
```
- 방장이 일시정지해도 **경기는 계속 흐른다.** 게스트 궤적·점령·킬 판정·남은 시간 모두 정상.
- 방장 본인은 잠금이 풀린 동안 `movePlayer`가 안 돌므로 **그 자리에 서 있는다.** 이건 그대로다.
  (서 있는 동안 새 칸을 안 밟으니 방장 궤적도 늘지 않는다.)
- 오프라인·게스트 동작은 바뀌지 않았다.

## 감독 확인 요청
한 PC에서 창 두 개로 붙어 주시면 그대로 재현·확인됩니다.
1. 방장 창에서 게임 시작 → **게스트 창을 클릭**(이때 방장 잠금이 풀린다).
2. 게스트로 한 바퀴 돌아본다.
3. 확인 포인트 — **남은 시간이 계속 줄어드는가.** 이게 멈춰 있으면 판정이 멎은 것이다.
   전에는 여기서 시계가 멈추고 궤적이 안 나왔다.
4. 게스트 궤적이 이어지는가, 한 바퀴 돌면 점령되는가.

## 남은 이슈
1. 방장 창을 **다른 탭 뒤로 완전히 숨기면** 브라우저가 `requestAnimationFrame`을 초당 1회 수준으로
   낮춘다. 이건 브라우저 정책이라 막을 수 없다. 다만 11번의 칸 잇기 덕분에 궤적은 끊기지 않고
   **느려질 뿐**이다. 방장 창은 최소화하지 말고 옆에 띄워두시길 권한다.
2. 상대 캐릭터는 여전히 18Hz로 툭툭 움직인다 (보간 없음). 궤적·점령 판정은 정확하다.
3. 09·10 문서의 미완 항목(치팅 방지 없음, 방장 이탈 시 종료, 자동 기동 미적용)은 그대로다.
