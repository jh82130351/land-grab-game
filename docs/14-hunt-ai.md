# 14 - 궤적 길이 제한 제거 + 봇 사냥 AI

## 무엇을 했나
1. **궤적이 길어지면 죽이던 규칙을 없앴다.** 이제 얼마든지 크게 둘러도 된다.
2. **크게 두르는 위험을 봇이 만든다.** 집에서 멀리 나와 궤적을 길게 드러낸 상대를
   봇이 찾아와 자른다. 사람 플레이어도 똑같이 대상이다.

규칙이 강제하던 제약을 **상대의 판단으로 옮긴 것**이 이번 작업의 전부다.

---

## 1. 제거 내역

`stepCell()`에 있던 이 줄이 사라졌다.
```js
// 한 번에 너무 크게 두르지 못하게 막는다. 이게 없으면 맵 외곽을 한 바퀴 돌아
// 한 방에 전부 먹는 수가 생긴다 (09 문서에 근거).
if (ent.trail.length >= TRAIL_CAP) kill(ent, ent, '궤적이 너무 길어 끊어짐');
```

함께 정리한 것.

| 대상 | 처리 |
| --- | --- |
| `const TRAIL_CAP = 320` (전역) | **삭제.** 죽는 기준이 없어졌으니 상수도 남길 이유가 없다 |
| 사망 사유 `'궤적이 너무 길어 끊어짐'` | **삭제.** 이제 발생하지 않는다 |
| HUD `궤적 224/320 위험` | **삭제.** 근거가 사라졌다. `궤적 224칸`으로만 보여 준다 |
| 봇의 `maxTrail` | **유지.** 죽는 상한이 아니라 "이쯤이면 돌아간다"는 봇 자신의 판단 기준이다. `TRAIL_CAP` 의존만 끊었다 |
| 궤적 인스턴스 상한 (`buildArena` 안) | 4,096 → **16,384.** 제한이 없어졌으니 넷이 동시에 크게 둘러도 안 넘치게 |

## 2. 사냥 로직

### 누구를 노리나
궤적을 밟으면 그 주인이 죽고 **땅을 전부 잃는다.** 어느 칸을 밟든 결과가 같으므로,
고를 때 보는 건 "얼마나 손해가 크고, 얼마나 잡기 쉬운가"다.

```js
const away = |적 위치 - 적의 집|;                     // 집에서 얼마나 나와 있나
if (away < HUNT_AWAY && 적.궤적길이 < HUNT_LONG) continue;   // 아직 안전권 — 안 건드린다

점수 = min(200, 적의 궤적길이)        // 길게 늘어놓을수록 (손해가 크다)
     + min(120, away) × 1.5           // 집에서 멀수록 (못 돌아가고 죽는다)
     - 나에게서의 거리 × 2;           // 내가 멀수록 깎는다
```
고른 상대의 궤적 중 **나한테 제일 가까운 칸**을 목표로 잡고 그리로 간다.
궤적이 아주 길면 띄엄띄엄(최대 400칸 표본) 훑어 비용을 묶어 둔다.

### '노출됐다'의 문턱 — 이게 없으면 경기가 망가진다
| 상수 | 값 | 뜻 |
| --- | --- | --- |
| `HUNT_AWAY` | 100칸 (150m) | 자기 집에서 이만큼 나와 있거나 |
| `HUNT_LONG` | 160칸 (240m) | 궤적을 이만큼 늘어놓았거나 |

둘 중 하나를 넘어야 사냥감이다. **문턱을 두지 않고 돌렸더니 봇끼리 평소 확장까지
서로 물어뜯어 평균 점유율이 7.3% → 5.0%로 무너지고 30판 중 24개체가 0%로 끝났다.**
봇의 일상적인 확장은 집에서 30칸 안팎이라 이 문턱 아래에 있고, 크게 한 바퀴 도는
쪽만 걸린다. 문턱을 바꿔 가며 잰 표는 아래 검증에 있다.

### 사냥 vs 확장
- 사냥감이 없으면 **평소처럼 확장한다.** 사냥은 판단 주기마다 확률(`aggr`)로 시도한다.
- **사냥 중에도 주기마다 다시 조준한다.** 상대가 궤적을 늘리며 다가오면 더 가까운 칸이
  생기는데, 처음 찍은 칸만 보고 있으면 그걸 놓친다.
- 그만두는 조건: 목표 칸이 사라졌거나(상대가 점령했다), 너무 오래 쫓았거나
  (`huntR × 2 + 20`칸), 내 궤적이 `maxTrail`을 넘었을 때.
- 쫓는 중에도 **위험 감지가 우선**이다. 내 궤적에 적이 붙으면 사냥을 접고 복귀한다.

## 3. 봇별 파라미터

| 배역 | 공격성 `aggr` | 사냥 사거리 `huntR` | 궤적 상한 | 성격 |
| --- | --- | --- | --- | --- |
| 확장형 | 0.05 | 18칸 (27m) | 275 | 거의 안 쫓는다. 땅만 넓힌다 |
| **사냥꾼** | **0.60** | **55칸 (82m)** | 150 | 멀리서도 달려온다. 자기 궤적은 짧게 유지 |
| 침투형 | 0.15 | 30칸 (45m) | 260 | 가는 길에 걸리면 친다 |
| 수비형 | 0.08 | 20칸 (30m) | 175 | 제 땅 지키는 쪽 |

매 판 배역을 섞어 나누고, 같은 배역도 값을 ±20~35% 흔든다 (13 문서).

## 4. 자멸 방지 — 그대로 유지

13에서 넣은 두 겹을 사냥 중에도 똑같이 적용한다. 추격은 **가고 싶은 방향의 순서**만
바꿀 뿐, 칸을 고르는 마지막 관문은 하나다.
```js
if (trail[다음칸] === b.id) continue;                  // 자기 궤적은 절대 안 밟는다
if (guard && routeHome(b, nx, nz) === -1) continue;    // 돌아올 길이 없으면 그 칸은 안 고른다
```
**검증 전체(봇전 160판 + 미끼 40회)에서 봇 자멸 0회다.**

## 검증

### (1) 길게 돌아도 안 죽는가 — 실제 브라우저
혼자 두고 맵을 크게 가로지르게 했다.
```
{"alive":false,"peakTrail":677,"meshCap":16384,"feed":"나 — 자기 궤적에 걸림","err":[]}
```
**궤적 677칸** — 옛 상한 320칸의 두 배를 넘겼는데 길이로는 죽지 않았다.
마지막에 죽은 건 검증 경로가 자기가 그은 선을 도로 밟았기 때문이고,
**자기 궤적 규칙은 그대로 살아 있다.** 런타임 오류 0건.

### (2) 봇이 실제로 자르러 오는가 — 미끼 40회
사람 대신 맵 한가운데를 크게 한 바퀴 돌게 했다. 네 귀퉁이의 집에서 50칸 넘게 떨어진
경로라, 여기서 잘리면 **우연히 마주친 게 아니라 봇이 찾아온 것**이다.

| | 구버전(13) | **신버전(14)** |
| --- | --- | --- |
| 봇에게 잘림 | 19/40 | **38/40** |
| 규칙에 죽음(`궤적 길어 끊어짐`) | 21/40 | **0/40** |
| 잘리기까지 평균 | 53.4초 | 45.5초 |
| 도달한 최대 궤적 | 평균 283칸 / 최장 **319칸**(상한에 막힘) | 평균 246칸 / 최장 **375칸** |
| 잡은 봇 | A 13 · B 1 · C 5 | **A 24 · B 4 · C 10** (셋 다 참여) |

걷기(6m/s)와 달리기(11m/s) 둘 다 돌려 봤으나 결과가 같다 (95% / 92%).
봇이 노리는 건 **이미 바닥에 깔린 궤적 칸**이라 도망쳐도 그 칸은 그 자리에 남는다.

### (3) 봇전이 망가지지 않았는가 — 각 40판
| | 구13 봇3 | **신14 봇3** | 구13 봇4 | **신14 봇4** |
| --- | --- | --- | --- | --- |
| 평균 점유율 | 6.35% | **6.39%** | 5.97% | **5.80%** |
| **봇 자멸** | **0회** | **0회** | **0회** | **0회** |
| 총 사망 | 35회 | 36회 | 63회 | 62회 |
| 0% 방치 | 21/120 | **10/120** | 23/160 | 23/160 |
| `궤적 길어 끊어짐` | 0회 | 0회 | 0회 | 0회 |

봇끼리의 경기는 13과 사실상 같다. 봇은 서로를 거의 안 쫓기 때문이다(문턱).

### (4) 문턱을 정한 근거 — 30판씩
| 문턱 | 봇전 평균 | 0% 방치 | 사망 | 미끼 잘림 |
| --- | --- | --- | --- | --- |
| 없음 | 5.00% | 24/90 | 62 | — |
| 집>46 또는 궤적>130 | 5.52% | 15/90 | 55 | 28/30 |
| 집>60 또는 궤적>110 | 5.79% | 16/90 | 47 | 29/30 |
| 집>80 또는 궤적>160 | 6.81% | 8/90 | 30 | 28/30 |
| **집>100 또는 궤적>160** | **6.97%** | **4/90** | **25** | **29/30** |
| 집>100 또는 궤적>190 | 6.37% | 14/90 | 25 | 27/30 |

**미끼를 자르는 비율은 문턱과 거의 무관하고(28~29/30), 봇전 건강만 달라진다.**
사람을 노리는 힘은 그대로 두고 봇끼리의 소모만 줄일 수 있다는 뜻이라 가장 높은 쪽을 골랐다.

### 눈으로 본 결과

빨강·초록 봇이 **자기 영역에서 나와 그 선까지 곧장 궤적을 뻗어 와 밟는다.**

## 알려진 이슈 / 밸런스 경고
1. **"외곽 한 바퀴로 한 방에 다 먹기"가 규칙상 가능해졌다.** 09 문서가 상한을 둔 이유가
   이것이었다. 지금은 봇이 막아 주지만 **봇이 못 오는 상황(멀리 떨어진 구석, 봇이 전부 사망 후
   리스폰 중)에서는 통한다.** 온라인 대전에는 봇이 없으므로 **사람끼리 붙으면 막을 장치가
   전혀 없다.** 여기에 대한 판단이 필요하다.
2. **사냥은 여전히 땅을 깎는다.** 사냥꾼 배역은 점유율이 낮게 나온다. 설계상 그렇다.
3. **도망쳐도 소용이 없다.** 봇은 바닥에 깔린 궤적 칸을 노리므로 달리기로는 못 벗어난다.
   벗어나는 방법은 **집에 닿아 점령을 끝내는 것**뿐이다. 의도한 대로인지 확인 부탁드린다.
4. 12·13 문서의 미완 항목(사망 페널티 전부 잃음, 치팅 방지 없음, 자동 기동 미적용)은 그대로다.

## 감독 확인 요청
1. **직접 크게 한 바퀴 돌아 보고 봇이 자르러 오는 게 체감되는지.** 미니맵에서 봇 궤적이
   내 선 쪽으로 곧장 뻗어 오는 게 보인다.
2. **사냥 강도가 적당한지.** 40회 중 38회가 잘렸다. 너무 빡빡하면 `HUNT_AWAY`·`HUNT_LONG`을
   올리거나 사냥꾼의 `huntR`(55칸)을 줄이면 된다.
3. **알려진 이슈 1번(온라인에는 봇이 없어 무제한이 그대로 노출된다)에 대한 방침.**
