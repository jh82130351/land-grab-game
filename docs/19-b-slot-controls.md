# 19-b - 스킬 슬롯 조작 (최종)

## 무엇을 했나
슬롯에 **선택 칸**이 생겼다. 항상 하나가 흰 테두리로 표시되고, 기본은 1번이다.
키·휠·우클릭 세 가지로 다룬다.

| 조작 | 동작 |
| --- | --- |
| **키 1 / 2 / 3** | 그 칸을 **고르고**(흰 테두리 이동) **들어 있으면 바로 쓴다**. 써서 비어도 **선택은 그 칸에 남는다** |
| **마우스 휠** | 선택 칸을 **1 → 2 → 3 → 1** 로 돌린다 (위로 굴리면 역방향) |
| **우클릭** | **지금 고른 칸**을 쓴다. 비어 있으면 아무 일도 안 일어난다 |

- 쓰면 그 칸이 비워진다. **빈 선택 칸에 새 아이템이 들어오면 우클릭만으로 바로 쓸 수 있다.**
- 경기 중에는 **우클릭 메뉴가 뜨지 않는다** (`contextmenu` 차단).
- 세 조작 모두 **포인터 잠금 상태에서만** 받는다. 일시정지 화면이 떠 있으면 안 먹는다 —
  키 1/2/3도 원래 그랬으므로 셋의 규칙이 같다.

---

## 구현

```js
// 선택 슬롯은 항상 하나다. 기본은 1번 칸.
// 순전히 내 화면의 조작 상태라 온라인으로 보내지 않는다 — 보내는 건 '몇 번 칸을 썼다'뿐이다.
let selSlot = 0;

function fireSlot(slot) {                       // 발동 통로를 하나로 모았다
  if (online && !iamHost) send({ t: 'relay', data: { k: 'u', s: slot } });
  else useSlot(me, slot);
}
```

```js
// 키 — 고르고, 들어 있으면 그대로 쓴다
selSlot = +e.code.slice(5) - 1;
fireSlot(selSlot);

// 휠 — 선택 칸을 돌린다
selSlot = (selSlot + (e.deltaY > 0 ? 1 : SLOTS - 1)) % SLOTS;

// 우클릭 — 지금 고른 칸을 쓴다
if (e.button === 2 && screen === 'game' && locked && !paused) fireSlot(selSlot);
```

**선택 칸은 온라인으로 보내지 않는다.** 게임 상태가 아니라 내 화면의 조작 상태이기 때문이다.
방장에게 가는 건 19단계 그대로 `{k:'u', s:칸번호}` 하나뿐이고, 휠이든 키든 우클릭이든
결국 같은 메시지가 된다. 그래서 **서버도 프로토콜도 손대지 않았다.**

HUD는 선택 칸에 `sel` 클래스를 붙여 흰 테두리와 안쪽 선을 준다.
경기를 새로 시작하면 선택은 1번 칸으로 돌아간다.

## 검증

### (1) 조작 전부 — 실제 브라우저에서 진짜 이벤트를 쏴서 확인
`KeyboardEvent` · `WheelEvent` · `MouseEvent(button:2)` 를 실제로 발생시켜,
**`selSlot` 값과 화면의 흰 테두리 위치가 같이 움직이는지** 함께 봤다.

| 동작 | 선택 | 흰 테두리 | 슬롯 |
| --- | --- | --- | --- |
| 경기 시작 직후 | 1번 | **1번** | `[000]` |
| 휠 아래 1회 | 2번 | **2번** | `[000]` |
| 휠 아래 2회 | 3번 | **3번** | `[000]` |
| 휠 아래 3회 | **1번 (순환)** | **1번** | `[000]` |
| 휠 위 1회 | **3번 (역방향)** | **3번** | `[000]` |
| 아이템 3개 보유 | 3번 | 3번 | `[123]` |
| **우클릭** (선택 3번) | 3번 | 3번 | `[120]` ← 3번 칸이 비었다 |
| 휠로 1번 이동 후 **우클릭** | 1번 | 1번 | `[020]` ← 1번 칸이 비었다 |
| **키 2** (선택+즉시 사용) | 2번 | 2번 | `[000]` ← 고르면서 바로 썼다 |
| **키 2 다시** (빈 칸) | 2번 | 2번 | `[000]` ← 아무 일 없다 |
| 빈 선택 칸에 새 아이템 | 2번 | 2번 | `[040]` |
| **우클릭으로 바로 사용** | 2번 | 2번 | `[000]` |

```
우클릭 메뉴 차단: True · 남은 효과 {부스트 6.0초, 무적 6.0초} · 런타임 오류 0건
```
**선택 칸과 흰 테두리가 모든 단계에서 일치했고, 써서 비워져도 선택은 그 칸에 남았다.**

### (2) 온라인 2인 — 게스트가 휠과 우클릭만으로 조작
게스트가 **키를 전혀 안 쓰고** 휠로 칸을 맞춘 뒤 우클릭으로만 발동하게 두고 돌렸다.
```
방장   ent1 슬롯[000] 땅0     조작: 휠→1번 우클릭 [100] / 휠→1번 우클릭 [400] / 휠→1번 우클릭 [100]
게스트 ent2 슬롯[000] 땅107   조작: 휠→1번 우클릭 [100] / 휠→1번 우클릭 [400]
전 클라 슬롯·땅 동일 : True
전 클라 아이템 동일  : True
오류 0건
```
게스트가 우클릭으로 쓴 `순간 귀환`이 방장에서 실행돼 **그 게스트 땅이 25칸(시작 블록) →
107칸**으로 늘었다. 두 화면의 슬롯·아이템·땅이 완전히 같다.

> 처음 돌렸을 때는 게스트 입력이 하나도 안 먹었다. 원인은 **게스트가 일시정지 상태**였기
> 때문이다. 게스트는 경기가 시작되면 `참가하기` 화면이 뜨고, 실제로는 화면을 클릭해야 풀린다.
> 시험 장치가 그 클릭을 안 해 줬던 것이고 코드 문제가 아니었다. 장치를 고쳐 다시 쟀다.

## 알려진 이슈
1. **포인터 잠금 자체는 헤드리스에서 못 건다.** 그래서 검증은 잠금이 걸린 것과 같은 상태
   (`locked = true`)를 만들어 놓고 진짜 이벤트를 쐈다. 휠·우클릭이 잠금 중에 전달되는 것은
   브라우저 표준 동작이지만, **실기에서 한 번 확인해 주시면 확실하다.**
2. 휠은 선택만 옮긴다. "휠로 고르고 곧장 발동"은 넣지 않았다 — 굴리다 실수로 쓰게 된다.
3. 19 문서에서 올린 판단 대기 건(궤적 무적에 튕긴 쪽의 구멍, 수치 조정)은 그대로다.

## 감독 확인 요청
1. **실기에서 휠과 우클릭이 잠금 중에 잘 먹는지** (알려진 이슈 1번).
2. 키를 눌렀을 때 **선택만 옮기고 쓰지는 않는 쪽**이 나은지, 지금처럼 **고르면서 바로 쓰는 쪽**이
   나은지. 지금은 지시하신 대로 바로 쓴다.
