# 10 - 게스트가 경기에 못 들어가던 버그 수정

## 증상 (정현 보고)
> 방장은 접속이 잘되는데 다른 플레이어는 방장이 시작하기를 눌러도 시작이 안 돼

## 원인 — 브라우저의 포인터 잠금 규칙
경기 진입은 `showScreen('game')` 직후 `requestPointerLock()` 을 부른다.
**브라우저는 사용자 조작(클릭·키입력) 직후가 아니면 포인터 잠금을 거부한다.**

| 역할 | 진입 계기 | 잠금 결과 |
| --- | --- | --- |
| 방장 | **[게임 시작] 클릭** → 곧바로 진입 | 조작 직후라 **허용** |
| 게스트 | **서버가 보낸 `game_start` 메시지** → 진입 | 조작이 없어 **거부** |

거부되면 `pointerlockchange` 이벤트 자체가 오지 않는다. 그래서 09단계에 넣어둔
"0.5초 뒤 갇힘 방지" 장치가 작동해 **일시정지 화면**이 떴다.
문구가 `일시정지 / 마우스 잠금이 해제되었습니다` 라서 **경기가 시작되지 않은 것처럼 보였다.**
게다가 그 상태에서는 이동도 위치 전송도 멈춘다(둘 다 잠금 상태를 조건으로 건다).
버튼 두 개 중 하나가 `메뉴로 나가기` 라 누르면 방에서 아예 빠져나간다.

**재현 확인**: 포인터 잠금 우회를 뺀 헤드리스 2인 테스트에서 게스트가
`screen=game / 오버레이=screen-pause / locked=false` 로 멈추는 것을 확인했다.
(09단계 검증에서는 자동화를 위해 잠금 조건을 우회했기 때문에 이 경로가 가려져 있었다.)

## 고친 내용
1. **경기 시작 시 안내를 전용 문구로 바꿨다.**
   `경기 시작! / 화면을 클릭하면 참가합니다 / [참가하기]`
   일시정지 화면을 재사용하되 제목·안내·버튼 글자를 상황에 따라 바꾸게 했다.
2. **오버레이 아무 곳이나 클릭해도 참가**된다. 버튼을 정확히 누를 필요가 없다.
3. **방장은 그대로 즉시 진입**한다. 클릭이 조작으로 인정되므로 잠금이 걸린다.
   혹시 거부되면 게스트와 같은 안내가 뜬다.

```js
if (iamHost) {                       // [게임 시작] 클릭 = 사용자 조작 → 바로 잠금
  requestLock();
  setTimeout(() => { if (screen === 'game' && !locked) joinPrompt(); }, 400);
} else {                             // 네트워크 메시지로 들어옴 → 클릭을 받아야 한다
  joinPrompt();
}
```

대기 중에도 **화면은 계속 갱신된다.** 방장이 보낸 상태는 잠금과 무관하게 반영되므로,
클릭 전에도 상대의 영역·궤적이 움직이는 게 보인다.

**실제 브라우저에서는 방장은 안내 없이 바로 들어가고, 게스트만 한 번 클릭하면 된다.**

## 알려진 한계
1. 게스트는 **클릭을 한 번 해야** 조작이 시작된다. 브라우저 정책이라 없앨 수 없다.
   대신 무엇을 하라는 안내를 명확히 했다.
2. 클릭 전까지 그 사람의 캐릭터는 제자리에 서 있다. 그동안 상대에게 궤적을 잘릴 일은 없지만
   (궤적이 없으므로) 시간은 흘러간다.
3. 09 문서의 미완 항목(보간 없음·치팅 방지 없음·방장 이탈 시 종료·자동 기동 미적용)은 그대로다.

## 감독 확인 요청
- 두 기기에서 다시 시도해 보시고, 게스트 쪽에 **"경기 시작! 화면을 클릭하면 참가합니다"** 가 뜨는지,
  클릭 후 정상적으로 움직이는지 확인 부탁드린다.
