## 구조 요약

### 격자 · 렌더 분리 (성능 핵심)
셀 로직은 **전부 타입 배열**이고 3D는 그 결과만 따라간다.
```js
owner = Uint8Array(40000)   // 0 빈땅, 1~4 소유자
trail = Uint8Array(40000)   // 0 없음, 1~4 궤적 주인
pix   = Uint8Array(160000)  // DataTexture 원본 (RGBA)
seen / queue                // flood-fill 재사용 버퍼 (매번 새로 할당하지 않는다)
```
- 바닥은 **200×200 DataTexture 한 장**이다. 셀 하나가 바뀌면 `paint(i)` 가 픽셀 4바이트만 고치고
  `texDirty` 를 올린다. GPU 업로드는 **프레임당 최대 1회**.
- **전체 재생성은 경기 시작 때 `paintAll()` 한 번뿐**이다.
- 궤적 낮은 벽은 `InstancedMesh` (용량 4096). 궤적이 바뀐 프레임에만 다시 채운다.
- flood-fill은 **궤적이 닫히는 순간에만** 돈다. 40,000칸 BFS라 한 번에 수 ms.

### 텍스처 방향
DataTexture는 상하를 뒤집지 않는데 평면을 -90° 눕히면 v=0이 월드 +Z가 된다.
그래서 행 번호는 `GRID-1-gz` 로 뒤집어 쓰고, **이 변환은 `paint()` 한 곳에만 둔다.**
미니맵도 같은 픽셀 버퍼를 쓰므로 그릴 때 한 번 뒤집어 맞춘다.

### 궤적 · 점령
`stepCell()` 이 규칙의 전부다. 참가자가 **새 셀에 들어간 순간**에만 돈다.
1. 그 칸에 궤적이 있으면 → **궤적 주인이 죽는다** (자기 궤적이면 자살).
2. 내 땅이면 → 그리던 궤적이 있을 때 `capture()`.
3. 내 땅이 아니면 → 그 칸을 내 궤적으로 기록.

`capture()`: 궤적을 내 땅으로 바꾼 뒤, **맵 바깥 테두리에서 flood-fill** 해서
"바깥과 이어지지 않은 칸"을 전부 내 땅으로 만든다. 남의 땅도 갇히면 먹는다.
갇힌 칸에 남의 궤적이 있었다면 그 주인도 죽는다.

### 죽음 · 리스폰
죽으면 **궤적과 점령지를 모두 잃고** 1.5초 뒤 빈 자리에 새 5×5로 부활한다.
플레이어도 같다 (게임오버가 아니라 계속 진행).

### 봇 AI
자기 땅에서 나가 **직사각형을 그리고 돌아온다.** 검증하면서 두 번 고쳤다.
- 회전 방향을 **한 번 정하면 끝까지 같은 방향**으로만 꺾는다. 랜덤으로 꺾으면 자기 궤적을 잘라 죽는다.
- **1번 변과 3번 변의 길이를 같게** 맞춰 사각형이 닫히게 했다. 길이가 다르면
  복귀 경로가 1번 변을 가로질러 자살한다. (이걸 고치기 전엔 봇 3명이 3분 내내 시작 영역만 갖고 있었다.)
- 한 변 18~52m. 두 칸 앞이 자기 궤적이면 꺾는 안전장치도 넣었다.
- 벽 근처에서는 안쪽으로 조향한다.

### 미니맵 · HUD
- 미니맵은 **격자 픽셀 버퍼를 그대로 재활용**한다 (`putImageData` → 확대). 140ms마다 갱신.
  그 위에 참가자 점을 찍는다. 내 점은 흰색.
- 점수판은 좌상단. **CSS `order` 로 순위대로 재배치**한다 (DOM 재생성 없음). 사망자는 흐리게.
- 타이머는 상단 중앙, 30초 이하에서 빨갛게.
- 하단 HUD에 내 순위 · 점유율 · 속도 · fps.

### 승패
제한시간 종료 또는 60% 도달 시 `endMatch()` → 순위표 화면.
`[다시하기]` 는 `initMatch()` 부터 다시, `[메뉴로]` 는 시작화면.

## 동작 검증 (헤드리스 크롬 실행)
렌더와 무관하게 격자 로직만 빠르게 돌리는 하네스를 만들어 **3분 경기를 끝까지** 돌렸다.
```
[t0s]   나 0.06% · 봇A 0.06% · 봇B 0.06% · 봇C 0.06%
[t30s]  나 3.38% · 봇A 0.51% · 봇B 1.47% · 봇C 1.35%
[t90s]  나 3.39% · 봇A 1.39% · 봇B 2.42% · 봇C 0.06%   ← 봇C 사망 후 리셋
[t150s] 나 3.39% · 봇A 0.06% · 봇B 4.22% · 봇C 3.15%
[종료]  나 3.39% · 봇A 2.76% · 봇B 4.24% · 봇C 5.93%   → 순위표 화면 출력
```
- 점령 면적이 기하학적으로 맞는지 확인했다. 반지름 30m 원을 그리면 2,827m² = **3.14%**,
  실제 결과 3.39%로 일치한다. flood-fill이 정상이라는 뜻이다.
- 스크린샷으로 **3D 점령지(색 칠해진 땅) · 궤적 낮은 벽 · 미니맵 · 점수판 · 타이머**를 눈으로 확인했다.
- 종료 화면(순위표 + 다시하기/메뉴로) 출력 확인.
- 런타임 오류 0건.

## 알려진 버그 · 미완
1. **봇이 여전히 가끔 자살한다.** 복귀 중 남의 궤적이 아니라 자기 궤적에 걸리는 경우가 남아 있다.
   위 로그에서 봇A·봇C가 중간에 0.06%로 리셋된 게 그것이다. 경기는 굴러가지만 봇 실력이 들쭉날쭉하다.
2. **봇이 상대를 노리지 않는다.** 마주쳐서 우연히 자르는 건 되지만 의도적으로 추격하진 않는다.
3. **충돌 판정 없음.** 참가자끼리, 그리고 궤적 벽을 그대로 통과한다 (규칙상 닿으면 죽으므로 통과 자체가 문제는 아님).
4. **점령률이 전반적으로 낮다.** 3분에 5% 내외라 60% 즉시 종료는 사실상 발동하지 않는다.
   맵이 300m로 넓은 탓이다. 승부는 제한시간으로 갈린다.
5. **플레이어 사망 시 점령지를 전부 잃는다.** Splix 규칙대로 했는데 체감상 가혹할 수 있다.
6. 모바일 미지원(포인터 잠금·키보드 전제), 로비는 05단계 그대로 유지.

## 감독 확인 요청 사항
1. **맵 크기 / 경기 시간 감각.** 300m·3분이면 점유율이 5% 언저리에서 승부가 난다.
   (a) 맵을 200m로 줄이거나 (b) 시간을 5분으로 늘리거나 (c) 이동속도를 올리는 세 방향이 있다.
   어느 쪽이 원하시는 그림인지 알려달라.
2. **60% 승리 조건을 유지할지.** 현재 설정에선 발동하지 않는다. 20~30%로 낮추는 편이 실효성 있다.
3. **사망 페널티** — 전부 잃는 방식 유지할지, 절반만 잃게 할지.
4. **봇 난이도** — 지금은 자기 땅만 넓히는 수준이다. 플레이어를 노리게 만들지 결정 바란다.
5. valuetopic `app.py`·`base.html` 변경이 아직 버전관리 밖에 있다 (03 문서 1번, 미해결).
