# 05 - 온라인 로비를 3D 이동형으로 교체

## 무엇을 했나
- 로비를 2D 버튼 목록에서 **걸어다니는 3D 실내 공간**으로 교체했다. 방은 문(포털) 오브젝트로 서 있고,
  가까이 가면 `[E] 입장` 프롬프트가 뜬다.
- 이동·시점·포인터 잠금 로직을 **게임과 로비가 공유**하도록 월드 구조를 분리했다.
- 실제 온라인 연결·땅따먹기 로직은 지시대로 **넣지 않았다.** 입장·방 만들기는 "준비 중" 토스트.

### 1. 월드 구조 분리 (핵심 변경)
씬이 2개가 되면서 "현재 어느 월드에 있는가"를 명시적으로 들고 있게 했다.
```js
const WORLDS = { game: buildField(), lobby: buildLobby() };
let world = WORLDS.game;
function enterWorld(name) { /* 스폰 위치·시선 초기화 */ }
```
각 월드는 `{ scene, limit, spawn, yaw, spots }` 형태다.
- `limit` — 월드마다 다른 경계 (평지 199m / 로비 18.8m). 이동 코드는 `world.limit` 만 본다.
- `spots` — 상호작용 지점 배열. 로비만 채워져 있고 평지는 빈 배열이다.
- **이동·점프·시점 코드는 한 벌 그대로다.** 월드가 늘어도 `update()` 는 건드릴 필요가 없다.
- 렌더는 `renderer.render(world.scene, camera)` — 카메라 하나를 두 씬이 공유한다.

### 2. 로비 공간
- 40m × 40m 실내. 바닥 타일(2m 체커), 벽 4면(높이 7m), 천장으로 덮어 실내감을 냈다.
- 안개를 18~48m로 좁게 걸어 벽 너머가 자연스럽게 어두워진다.
- 조명: ambient + hemisphere + 방향광 + **천장등(PointLight)**.
  천장등은 헤드리스 스크린샷으로 확인하다 안쪽 벽이 새까맣게 죽길래 추가했다.
- 스폰은 방 문 반대편(z +9)이고 **시선이 문 쪽을 향하도록** yaw를 잡았다.
  (처음엔 yaw를 180°로 줘서 반대(방 만들기 쪽)를 보고 시작했다. 스크린샷으로 잡아 고쳤다.)

### 3. 방 오브젝트
각 방은 **발판 + 문틀 + 빛나는 문면 + 포인트라이트 + 라벨** 5개로 구성된다.
- 상태에 따라 색이 다르다. **대기 = 초록**, **진행 = 주황**. 진행 중인 방은 문면 투명도를 낮춰 어둡게 보인다.
- 라벨은 캔버스에 그려 `THREE.Sprite` 로 띄운다 (이름 + `1 / 2 · 대기`).
  항상 카메라를 향하므로 어느 각도에서 접근해도 읽힌다.
- 문은 안쪽 벽을 따라 7.5m 간격 일렬 배치. 방 개수가 바뀌면 자동으로 가운데 정렬된다.

### 4. 근접 상호작용
```js
const REACH = 3.2;   // m
```
- 매 프레임 `spots` 중 **수평거리 기준 가장 가까운 것 하나**를 고른다 (y는 무시 — 점프 중에도 유지).
- 프롬프트는 조준점 아래 고정 오버레이. `[E] 입장  연습방 · 1/2 · 대기` 형태로 대상까지 같이 보여준다.
- `E` → 방이면 "온라인 대전 준비 중입니다 (08단계) — 방이름", 발판이면 "방 만들기 준비 중입니다".
- 텍스트는 전부 `textContent` 로만 넣는다. `innerHTML` 은 쓰지 않았다 (서버가 줄 방 이름이 들어올 자리).

### 5. 방 만들기 존
반대편(z +15)에 금색 발판 + 빛기둥 + 라벨. 멀리서도 "저기 뭔가 있다"가 보이도록 빛기둥을 세웠다.

### 6. 방 데이터
```js
const ROOMS = [ { id, name, players, max, state } ];   // state: 'wait' | 'play'
```
08단계에서 **서버 응답이 이 배열로 그대로 들어오는 형태**다. 현재 3개(대기2·진행1)가 예시로 들어 있다.

### 7. ESC / 뒤로 흐름
| 상황 | 동작 |
| --- | --- |
| 로비에서 ESC | 포인터 잠금 해제 → **메뉴 복귀** (지시대로) |
| 게임에서 ESC | **일시정지 화면** (계속하기 / 메뉴로) |
| 잠금 요청이 거부된 경우 | 0.5초 뒤 확인해 일시정지 화면 — 조작 불가 화면에 갇히지 않는다 |
| 잠금이 안 걸린 상태의 ESC | 이벤트가 안 오므로 키 입력에서 직접 처리 |
- 로비 상단에 안내 띠를 고정 노출한다: "온라인 서버 미연결 — 08단계 예정 / 문 앞으로 걸어가 E · 나가려면 ESC"
- HUD는 화면별로 항목이 바뀐다 (로비에서만 `E 상호작용`·`ESC 메뉴로`, 게임에서만 `ESC 일시정지`).

## 문법 검사 결과 (node --check 통과 여부)
- `<script type="module">` 520줄 추출 → **`node --check` 통과** (`.mjs` 확장자).
- `<script type="importmap">` JSON **파싱 통과**.
- `getElementById` 대상 **15개 전부** HTML에 존재 → 누락 0건.
- **추가: 헤드리스 크롬 실행 검증.** 실제로 페이지를 띄워 확인했다 (`--enable-unsafe-swiftshader`).
  - 런타임 오류 없음 (오류 표시 영역 비어 있음, 콘솔 에러 없음)
  - 메뉴 화면 정상 렌더
  - 로비 화면: 문 3개 + 라벨(`연습방 1/2 대기`, `빠른대전 2/2 진행`, `초보 환영 0/2 대기`) 정상
  - 문 앞 접근 시 `[E] 입장 연습방 · 1/2 · 대기` 프롬프트 표시 확인
  - **이 검증으로 스폰 시선 반대 방향 버그를 잡아 고쳤다.** 문법 검사만으로는 절대 안 잡혔을 문제다.

## 감독 확인 요청 사항 / 남은 이슈
1. **로비 크기·조명 감각 컨펌.** 40m는 3개 방 기준으로 넉넉한 편이라, 스폰에서 문까지 25m를 걷는다.
   좁은 게 나으면 줄이겠다. 실내가 어둡다는 느낌이면 조명도 같이 올리겠다.
2. **방 목록 3개는 여전히 가짜 데이터.** 방이 많아지면(10개+) 일렬 배치가 벽을 넘는다.
   그때는 벽 둘레 배치나 페이지 전환이 필요하다. 최대 몇 개까지 상정할지 알려달라.
3. **로비 ESC는 일시정지 없이 곧바로 메뉴로 나간다** (지시대로). 다만 알트탭으로 잠금이 풀려도
   메뉴로 튕긴다. 게임처럼 일시정지를 거치게 바꿀지 판단 바란다.
4. **충돌 판정이 없다.** 문틀·발판을 그대로 통과한다. 로비에선 크게 어색하지 않지만
   필요하면 원기둥 충돌을 넣겠다.
5. **게임 방식은 여전히 미확정.** 06단계 이후 땅따먹기 로직은 이것 없이는 못 간다.
   턴제/실시간, 인원, 보드 크기, 승리 조건 부탁드린다.
6. 모바일 미지원, valuetopic `app.py`·`base.html` 버전관리 밖 문제는 그대로다 (03 문서 1번).
