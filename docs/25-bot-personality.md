# 25 - 온라인 빈자리 봇 대체 + 봇 성향 랜덤(전원 고수) + 실수

## 무엇을 했나
1. **온라인에서 정원이 덜 차도 시작한다.** 빈 자리 수만큼 봇이 들어오고, 방장이 계산해
   전원에게 뿌린다. 14·15·16 문서가 세 번 올렸던 "온라인에는 봇이 없다"가 이걸로 닫힌다.
2. **봇 난이도 차등을 없앴다.** 판단 정확도는 전원 같은 값이고, 성향은 "뭘 우선하나"만 바꾼다.
3. **성향 6종**을 매 판 봇마다 하나씩 배정하고 순위표에 고유 색으로 붙인다.
4. **실수**를 넣었다. 경로를 다시 정하는 시점마다 1% 확률로 한 가지가 걸린다.

## 1. 온라인 빈자리 봇

### 바뀐 곳
| 위치 | 전 | 후 |
| --- | --- | --- |
| `ws_server.py` `start_game` | `if not room.full:` → 거부 | `if not room.members:` → 방장만 있으면 시작 가능 |
| 클라 `[게임 시작]` 핸들러 | 정원 미달이면 토스트 띄우고 중단 | 그대로 보낸다. 채울 칸 수를 토스트로 알린다 |
| `netStartMatch()` | `defs = members` | 뒤에 `room.max - members.length` 개의 봇 `defs`를 붙인다 |
| 대기실 안내문 | `참가자를 기다리는 중…` | `참가자 2 / 4 · 지금 시작하면 빈자리 2칸은 봇이 채웁니다` |

### 왜 서버·게스트가 안 어긋나는가
```js
const slots = Math.min(4, room.max || members.length);
for (let k = defs.length; k < slots; k++)
  defs.push({ name: '봇 ' + String.fromCharCode(65 + k - members.length), bot: true });
```
봇 개수와 이름을 **`room.max`와 `members`만으로** 정한다. `game_start` 메시지는 같은 방
전원에게 같은 내용으로 가므로 **모든 클라가 똑같은 명단을 만든다.** 슬롯 번호도 같다.

움직이는 건 방장뿐이다. `stepMatch()` 첫 줄이 그대로다.
```js
if (online && !iamHost) return;      // 게스트는 방장이 보낸 결과만 그린다
```
게스트는 `applyState()`로 좌표·땅·궤적·슬롯을 받아 그린다. **host-authoritative 그대로다.**

### 성향은 스냅샷에 실어 보낸다
`entPayload()` 마지막 칸에 성향 번호(1~6, 사람은 0)를 붙였다. 숫자 하나다.
```js
e.bot && e.ai ? e.ai.pi : 0
```
한 번만 보내면 그 메시지를 놓친 게스트가 끝까지 엉뚱한 성향을 그린다. **매 틱 실어
보내면 자가 복구된다.** 서버 프로토콜은 안 건드렸다 — relay가 임의 데이터를 그대로 넘긴다.

### 사람이 중간에 나가면 — 봇으로 대체하지 않는다 (판단)
`checkSilent()`는 지금도 그 사람을 `waiting`으로 표시하고 화면에 `응답 없음`을 띄운다.
그 자리를 봇으로 바꾸지 **않기로** 했다. 이유 셋.

1. **되돌릴 길이 없다.** 엔티티는 `netId`에 묶여 있고, 그 사람이 다시 들어오면 방장이
   조작권을 돌려줘야 하는데 그런 경로가 없다. 봇이 계속 몰고 있는 땅을 어떻게 넘길지도 미정이다.
2. **남의 땅을 방장이 움직이게 된다.** 이미 먹은 땅과 그어 둔 궤적이 그대로 있는데
   봇이 이어받으면, 남은 사람들이 동의하지 않은 방식으로 순위가 바뀐다.
3. 지금은 **가만히 서 있는 장애물**로 남는다. 17 문서의 유예·표시가 이미 그 상태를 보여 준다.

넣으려면 `checkSilent()`에서 `e.bot = true` 로 돌리고 `assignBrains()`를 다시 부르면 된다
(한 줄 수준). **재접속 경로를 먼저 정해야 한다**고 보고 보류했다.

## 2. 실력은 전원 같다

성향이 "약한 봇 / 센 봇"이 되지 않게, 판단 정확도에 해당하는 값을 **한 곳에 모아 공유**한다.
```js
const BOT_SKILL = {
  period: 0.8,     // 판단 주기(초)   — 전 1.1~1.8 (배역마다 달랐다)
  whim:   0.22,    // 방향 선택의 변덕 — 전 0.25~0.60
  sprint: 0.85,    // 달리기 적극성   — 전 0.35~0.85
};
```
- 14 문서의 **사냥 로직**, 15 문서의 **달리기 판단**(`urgency`·`pathClear`), 16 문서의
  **위협 인식**(`isSafeFoe`·`SORTIE`·`DODGE`)은 전원 같은 코드·같은 상수로 돌아간다.
- **자멸 방지는 손대지 않았다.** 칸을 고르는 마지막 관문이 13 문서 그대로다.
  ```js
  if (trail[다음칸] === b.id) continue;                  // 자기 궤적은 절대 안 밟는다
  if (guard && routeHome(b, nx, nz) === -1) continue;    // 돌아올 길이 없으면 안 고른다
  ```
- `sprint`를 전원 0.85로 통일했는데도 **실제로 달린 비율은 성향마다 다르게 나온다**
  (24.7% ~ 43.5%). `urgency()`가 국면마다 다른 값을 내므로, 아이템을 자주 쫓는 성향이
  자연히 더 달린다. 실력을 같게 두고도 차이가 생기는 지점이다.

## 3. 성향 6종

매 판 섞어 뽑으므로 같은 판에 같은 성향이 겹치지 않는다. 순위표에 이름이 **고유 색**으로 붙는다.

| 성향 | 색 | 공격성 `aggr` | 사냥거리 `huntR` | 아이템우선 `item` | 확장크기 `size` | 복귀민감도 `flee` | 궤적기준 `maxTrail` | 특수 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| **수집가** | `#35c9c0` 청록 | 0.18 | 26 | **1.8** | 22 | 20 | 220 | 사냥 중에도 아이템 들른다 |
| **저격수** | `#ff5a4e` 빨강 | **0.85** | **70** | 0.6 | 16 | 18 | 150 | `lock` 한 상대 고정 추격 |
| **만능** | `#e8edf5` 흰 | 0.40 | 40 | 1.0 | 22 | 20 | 240 | — |
| **돌격** | `#ff9b3d` 주황 | 0.70 | 50 | 0.8 | 26 | **10** | **300** | `press` 회피 감점 ×0.35 |
| **확장** | `#8fd14f` 연두 | **0.10** | 22 | 1.0 | **32** | 22 | **320** | 사냥은 기회만 |
| **교란** | `#b48cff` 보라 | 0.50 | 45 | 0.9 | 18 | **24** | 200 | `harass` 남의 궤적 근처 가산점 |

같은 성향도 값을 ±15~20% 흔들어 개체차를 준다. **실력에 해당하는 세 값은 흔들지 않는다.**

### 성향이 코드에 닿는 곳
| 성향 | 구현 |
| --- | --- |
| 수집가 | `findItem` 반경 `26 × item` = 47칸, `pickDir` 아이템 가산점 `6 × item`, **`hunt` 중에도 아이템으로 전환** |
| 저격수 | `pickLock()`으로 1위·최근접 중 하나를 고정, `findPrey(b, r, lockId)`가 그 상대만 본다. 고정 표적은 사냥 문턱(`HUNT_AWAY`·`HUNT_LONG`)을 **0.45배로 낮춰** 본다 — 실력이 아니라 "이 사람만 노린다"는 우선순위다. 표적이 죽으면 새로 고른다 |
| 돌격 | `pickDir`의 회피 감점 `DODGE × 0.35`(수비 약함) + 남의 궤적 칸 **+5**(압박). `flee 10`·`maxTrail 300`으로 **길게 노출하고 늦게 돌아온다** |
| 확장 | `size 32`·`maxTrail 320`, `aggr 0.10`으로 사냥은 거의 안 한다 |
| 교란 | 남의 궤적 칸 **+3.5**로 근처를 노리면서도 **회피 감점은 그대로** 받는다 → 교전은 신중 |
| 만능 | 전부 중간값 |

### 스킬 사용
19 문서의 규칙을 유지하고 두 군데만 고쳤다.
| 스킬 | 쓰는 때 |
| --- | --- |
| 궤적 무적 | 위험할 때 (`trail > 25 && threat < flee × 1.4`) |
| 속도 부스트 | 사냥 추격 중 · 위험한 복귀 중 |
| 순간 귀환 | 위험하고 궤적이 60칸 넘을 때 |
| 점령 확대 | **큰 폐곡선을 닫을 때** — 복귀 중 `trail > 40`, 또는 확장 중 `trail > maxTrail × 0.55` (전: 확장 중 `trail > 20`) |
| 자리 비우기 | 슬롯이 꽉 찼고 **궤적이 8칸 넘었을 때만** 덜 급한 걸 태운다 (전: 조건 없음 → 집에서 그냥 버렸다) |

## 4. 실수 — 판정 1%

```js
const MISTAKE_P = 0.01;
function rollMistake(b) {            // 판단 주기(0.8초)마다 한 번 굴린다
  b.miss = Math.random() < MISTAKE_P ? MISTAKES[(Math.random() * MISTAKES.length) | 0] : null;
}
const use = (k) => { if (b.miss === k) { b.miss = null; return true; } return false; };
```
걸리면 **그 판단 한 번만** 비틀고 바로 풀린다 (`use`가 꺼내 쓰면서 지운다).

| 실수 | 구현 | 결과 |
| --- | --- | --- |
| 도망 거리 2칸 부족 | `fleeTh = ai.flee - 2` | 복귀를 2칸 늦게 시작한다 |
| 복귀 한 박자 늦음 | `holdHome` → `phase = 'home'` 전환 건너뜀 | 한 주기(0.8초) 더 나가 있는다 |
| 아이템 쓸 타이밍 놓침 | `botUseSkill()` 호출 건너뜀 | 그 주기에 스킬을 안 쓴다 |
| 상대 궤적 오판해 접근 | 후보 방향 맨 앞에 **남의 궤적 쪽**을 끼워 넣는다 | 위험한 쪽으로 한 걸음 들어간다 |
| 회전 한 칸 늦게 꺾음 | 변이 끝나도 `phase` 전환을 미룬다 | 도형이 한 칸 길어진다 |
| 정면 승부 · 한 칸 먼저 꺾음 | 적이 10칸 안일 때 `legLeft = 0` | 먼저 돌아선다 |
| 정면 승부 · 물러날 타이밍 늦음 | 적이 10칸 안일 때 복귀 전환 건너뜀 | 한 박자 더 버틴다 |
| 정면 승부 · 궤적 길이 오판 | `aggr` 주사위를 건너뛰고 사냥 전환 | 질 싸움을 건다 |

**즉사하는 실수는 없다.** 전부 "위험해지는" 수준이고, 자멸 방지 관문은 실수와 **별개로**
늘 돌아간다. `misread`도 방향 **순서**만 바꾸고, 자기 궤적·복귀 경로 검사는 그대로 통과해야 한다.

## 검증

측정 장치는 레포에 안 들어가는 **계측 사본**(`/tmp/lgtest`)이다. 실제 브라우저(헤드리스 크롬)에서
`stepMatch()`를 그대로 돌리고, 사람은 13~16 문서의 봇전 기준선처럼 **자기 시작 칸에 가만히 서 있다.**

### (1) 구버전과 같은 하네스로 공정 비교 — 각 20판 (봇3 · 180초)
| | 구(HEAD `2255f0e`) | **신(25)** |
| --- | --- | --- |
| 평균 점유율 | 6.52% | **6.25%** |
| 0% 방치 | 0/60 | **0/60** |
| **봇 자멸** | **0회** | **0회** |
| 피살 | 13회 | **24회** |
| 아이템 획득 | 203개 | 209개 |
| 스킬 사용 | 158회 | 157회 |

**점유율은 사실상 그대로고(−0.27pt), 자멸은 0을 유지했다.** 피살이 13 → 24로 늘었다 —
성향 평균 공격성이 0.22 → 0.455로 올랐으니 서로 더 자주 잡는다. 설계한 방향이다.

### (2) 성향이 눈에 띄게 다른가 — 40판 (봇3 · 180초, 개체 120)
| 성향 | n | 평균 점유 | 사망/판 | 달림 | 최고 궤적 | 사냥한 판 |
| --- | --- | --- | --- | --- | --- | --- |
| 만능 | 20 | **7.11%** | 0.35 | 27.4% | 186 | 8/20 |
| 돌격 | 21 | 6.71% | 0.38 | 29.9% | **228** | 10/21 |
| 저격수 | 21 | 6.49% | **0.19** | 28.6% | **147** | **12/21** |
| 교란 | 19 | 6.27% | **0.16** | **24.7%** | 174 | 11/19 |
| 수집가 | 21 | 5.87% | 0.52 | **43.5%** | 227 | **2/21** |
| 확장 | 18 | 5.36% | **0.61** | 31.8% | **237** | **1/18** |

지시한 그림이 수치로 나온다.
- **확장**은 궤적이 가장 길고(237) 사냥은 40판에 **1번만** 한다. 그만큼 가장 많이 죽는다(0.61).
- **저격수**는 자기 궤적을 가장 짧게 유지하고(147) 가장 적게 죽으면서(0.19) **가장 자주 사냥한다**(12/21).
- **수집가**는 가장 많이 달린다(43.5%) — 아이템을 쫓아다닌다. 사냥은 2/21뿐이다.
- **교란**은 가장 적게 죽고 가장 적게 달린다 — 교전에 신중하다.
- **돌격**은 궤적을 길게 노출한다(228, 2위).
