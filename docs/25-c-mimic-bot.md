# 25-c - 봇 성향 '학습형(모방)' 추가

## 무엇을 했나
사람 플레이어만 관찰해 **"어떻게 노는지"를 요약값으로 쌓고**, 학습형 봇이 그 값으로 자기
파라미터와 도형을 정한다. 머신러닝이 아니라 **누적 평균**이다. 상대를 잡으려는 분석이 아니라
**사람처럼 움직이기**가 목적이다.

---

## 1. 사람 플레이 프로파일

봇은 관찰하지 않는다 — 봇이 봇을 베끼면 값이 제자리에서 맴돈다.
온라인에서는 `stepMatch()`를 방장만 돌리므로 **프로파일도 방장 로컬**에 쌓인다.

| 항목 | 무엇 | 어디서 재나 |
| --- | --- | --- |
| `trail` | 한 번 나갔다 올 때 궤적 길이 | `capture()` / `kill()` 시점의 `trail.length` |
| `turns` | 그 동안 꺾은 횟수 | `stepCell()` 마다 방향이 바뀌면 +1 |
| `run` | 직진 구간 길이 | 꺾을 때마다 직전 구간 길이를 평균 |
| `area` | 둘러싼 면적 | `capture()` 가 돌려준 `gained` (성공분만 따로 셈) |
| `away` | 집에서 가장 멀리 나간 거리 | 매 프레임 맨해튼 거리의 최댓값 |
| `hunt` | 궤적을 드러낸 시간 중 남의 궤적 8칸 안에 있던 비율 | `profTick()` 에서 `foeTrailDir(e, 8)` |
| `sprint` | 움직인 시간 중 달린 비율 | 프레임 간 이동 속도가 `(걷기+달리기)/2` 를 넘으면 |
| `hold` | 아이템을 슬롯에 넣고 쓰기까지 걸린 시간 | `takeItem` 시각 ↔ `useSlot` 시각 |
| `cw` | 꺾을 때 오른쪽을 고른 비율 (선호 방향) | 방향 전환의 좌/우 |

- **실시간 갱신**은 가볍게 — 칸을 밟을 때 한 번(`profStep`), 프레임마다 거리/속도 한 번(`profTick`).
- **한 번의 출격이 끝날 때**(점령 또는 사망) 누적 평균에 합산한다(`profEnd`). 6칸 미만은 버린다.
- **실패한 출격(사망)도 표본에 넣는다.** 위험한 스타일이면 그 위험까지 흉내내야 하기 때문이다.
  다만 `area` 는 점령 성공분만 센다.

```js
const PROF_CAP = 120;   // 표본 상한. 넘으면 최근 쪽에 1/120 씩 끌려가 변화를 따라간다
const PROF_MIN = 3;     // 이만큼 쌓이기 전에는 모방하지 않고 '만능'으로 둔다
```

## 2. 판 간 기억
`localStorage['lg.humanProfile.v1']` 에 **요약값만** 저장한다 (위 10개 숫자).
판이 끝날 때(`endMatch`) 저장하고, 부팅 때 한 번 읽는다.
**읽기·쓰기 모두 try/catch** — 시크릿 모드나 저장소 차단이면 조용히 무시하고 그 판만 쓴다.
깨진 값이 들어 있어도 `JSON.parse` 실패를 삼키고 처음부터 시작한다.

## 3. 모방 — 스타일만 옮긴다

```js
size     = 직진길이 × 1.1 + 출격거리 × 0.25        // 얼마나 크게 도나
maxTrail = max(궤적 × 1.3, (꺾기+1) × 직진 × 1.25)  // 제 도형 둘레보다 짧으면 안 된다
aggr     = 사냥비율 × 1.6
huntR    = 20 + 사냥비율 × 60
item     = 1.5 − 쥐고있던시간 / 8                   // 아껴두는 사람이면 덜 찾는다
useFast  = 1 − min(1, 쥐고있던시간 / 8)             // 즉시형이면 스킬 문턱이 낮아진다
flee     = 26 − 궤적 / 18                           // 길게 다니면 복귀에 둔감
sprint   = 0.45 + 달리기비율 × 0.5                  // 아래를 0.5 로 잘라 실력은 지킨다
```
전부 **± 10~25% 랜덤**을 섞고 범위를 자른다. 도형은 따로 만든다.

```js
function mimicShape(b) {                 // 꺾는 횟수와 직진 길이를 그대로 쓴다
  const n = clamp(2, 10, round(turns × (0.8~1.3)));
  const t = Math.random() < cw ? 1 : -1;        // 사람이 더 자주 꺾던 쪽
  legs = n+1 개, 각 변 = run × (0.7~1.4);
}
```
**큰 네모로 돌던 사람이면 변이 길고 적게, 지그재그면 짧고 많이** 나온다.

## 4. 실력은 그대로
- `period`·`whim` 은 `BOT_SKILL` 공유값 그대로. **판단 정확도는 다른 성향과 같다.**
- **자멸 방지는 손대지 않았다** — 칸을 고르는 마지막 관문(`trail[다음칸] === b.id`,
  `routeHome() === -1`)은 13 문서 그대로다.
- **1% 실수 그대로** 적용된다.
- `sprint` 하한 0.5, `maxTrail` 상한 400 등으로 **사람 스타일이 위험해도 자멸까지는 안 간다.**

## 검증

> **한계를 먼저 적는다.** 나는 화면 있는 브라우저를 띄울 수 없어 **헤드리스 크롬**으로 돌렸고,
> '사람'은 내가 **대본대로 걷게 만든 가짜 사람**이다 (`pos` 를 일정 속도로 목표 칸에 옮긴다).
> 관찰·누적·모방 경로는 게임 코드 그대로 타지만, **정현이 실제 마우스로 논 것과는 다르다.**
> 아래 ①②③ 은 그 전제에서 읽어 주시기 바란다.

### ① 데이터가 없을 때 — 만능처럼 시작하는가
```
프로파일 n=0 → 학습형 봇: mimic적용=False · size 19 · aggr 0.42 · maxTrail 264 · prof null
                          (만능 기본 22 / 0.40 / 240 에 개체차 ±15~20%)
```
모방을 켜지 않고 만능 값 그대로 간다. **첫 판·시크릿 모드에서 그대로다.**

### ② 스타일을 바꿔 3판씩 — 봇이 따라오는가
가짜 사람을 두 가지로 걷게 했다.
- **큰 네모**: 18칸짜리 변 4개, 꺾기 3번, 걷기(약 5.6 m/s)
- **지그재그**: 4칸씩 번갈아 꺾으며 나갔다가 남의 궤적 쪽으로 파고든 뒤 복귀, 달리기(약 11 m/s)

| | 큰 네모 3판 | 지그재그 3판 |
| --- | --- | --- |
| **사람** 꺾기 | 3.0회 | 11.0회 |
| **봇** 꺾기 | **3.2회** | **9.4회** |
| **사람** 직진 구간 | 17.3칸 | 6.4칸 |
| **봇** 변 길이 | **17.8칸** | **6.9칸** |
| **봇** sprint | **0.50** | **0.86** |
| 봇 자멸 | 0회 | 0회 |

봇이 실제로 그린 도형:
```
큰 네모 학습 후 : legs [20, 17, 15, 23]                       (꺾기 3)
지그재그 학습 후: legs [7, 7, 5, 7, 8, 5, 6, 8, 5, 8, 8]      (꺾기 10)
```

### ③ 값 → 파라미터 변환 (프로파일을 직접 꽂아 변환만 확인)
가짜 사람이 실제로 남의 궤적에 붙지 못해 `hunt` 가 0으로만 나왔다.
그래서 **사냥·아이템 항목은 게임 플레이가 아니라 변환만** 따로 확인했다.
```
사람 사냥비율 0.05 → 봇 aggr 0.06
사람 사냥비율 0.35 → 봇 aggr 0.42
사람 사냥비율 0.70 → 봇 aggr 0.95
아이템 쥐고 있던 시간 0.5초 → item 1.57 (즉시형)
아이템 쥐고 있던 시간 7.0초 → item 0.51 (아껴두는형)
```
**`hunt` 가 실제 플레이에서 제대로 쌓이는지는 미검증이다.** 아래 확인 요청 2번에 적었다.

### ④ 저장소
```
깨진 JSON 이 들어 있을 때 profLoad(): ok (안 죽고 처음부터 시작)
```
시크릿 모드(쓰기 거부)는 `try/catch` 로 감쌌지만 **헤드리스에서 거부 상태를 못 만들어

## 감독 확인 요청 / 남은 이슈
1. **직접 몇 판 돌고 나서 학습형 봇이 내 스타일로 도는지 봐 주시기 바란다.** 이게 진짜 검증이다.
   내 검증은 대본대로 걷는 가짜 사람이라, 사람이 실제로 내는 불규칙함은 들어가 있지 않다.
   콘솔에 `localStorage['lg.humanProfile.v1']` 을 찍으면 내 스타일이 어떻게 기록됐는지 보인다.
2. **`hunt`(사냥 비율)가 실제 플레이에서 쌓이는지 미검증이다.** 내 가짜 사람은 남의 궤적까지
   못 따라붙어 0으로만 나왔다. 몇 판 공격적으로 놀아 보신 뒤 위 저장값의 `hunt` 가 올라가 있으면
   그걸로 확인된다. 0에서 안 움직이면 8칸 문턱을 넓혀야 한다.
3. **표본 문턱 `PROF_MIN = 3`.** 한 판에 보통 여러 번 나갔다 오니 1판이면 켜질 수도 있다.
   "3판은 봐야 한다"가 맞으면 문턱을 8~10으로 올리면 된다.
4. **프로파일은 사람 전체를 한 덩어리로 섞는다.** 온라인에서 여러 명이 다른 스타일로 놀면
   평균이 나온다. 사람별로 나눌지는 판단이 필요하다.
5. 26 문서의 64칸 문턱, 26-b 의 재접속 복귀, 25 문서의 판단 네 건은 그대로다.
